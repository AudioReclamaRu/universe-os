**Дата:** 2026-11-25  
**Статус:** строгий числовой разбор и фиксированный порядок ссылок внедрены; CI success  
**Назначение:** предотвратить потерю числового значения при преобразовании JSON в float и сделать диагностику нескольких ошибочных ссылок Schema воспроизводимой.

## 0. Исходное основание

Документы 61–63 закрыли недопустимые JSON-токены, повторяющиеся ключи, семантику целых чисел и нормализацию путей. Дополнительная проверка выявила два остаточных риска:
- корректный по грамматике JSON числовой токен может превратиться в бесконечность либо в ноль при преобразовании в IEEE-754 float;
- порядок обхода нескольких ссылок Schema не должен зависеть от случайного порядка Python-множества.

Оба риска устранены.

## 1. Переполнение числового значения JSON

Строгий парсер уже отклонял буквальные токены NaN, Infinity и -Infinity через parse_constant. Но выражение 1e999 — это иной случай: сам токен соответствует числовой грамматике JSON, однако стандартное преобразование Python float возвращает inf.

Если такое значение дойдёт до схемы или семантической логики:
- разные библиотеки могут трактовать его по-разному;
- число перестаёт иметь конечное машинное представление;
- математические сравнения и проверка диапазона теряют ожидаемый смысл.

Добавлена функция _strict_json_float(token):
1. разбирает токен в float;
2. параллельно проверяет его точное десятичное значение через Decimal;
3. отклоняет результат, не являющийся конечным float;
4. возвращает значение только при сохранении ненулевого представления.

Таким образом, переполнение отклоняется уже на уровне чтения JSON.

## 2. Потеря ненулевого значения при underflow

Число 1e-999 не равно нулю, но стандартный float может представить его как 0.0. Если незаметно принять такое преобразование, исходный паспорт будет содержать ненулевое значение, а Python-объект — нулевое.

Парсер теперь сравнивает результат float с точным Decimal:
- если float равен нулю;
- и точное Decimal не равно нулю;
- вход отклоняется как значение ниже поддерживаемой числовой точности.

Запись 0.0 остаётся допустимым числом; она не приравнивается к underflow. Дальнейшее решение о допустимости нуля зависит от конкретного поля и его ограничений схемы/семантики.

## 3. Чрезмерно большие целые значения

В отличие от float, Python int может хранить очень большие целые числа. Но прикладной код может переводить их в float для проверки конечности или расчёта длительности.

Поэтому:
- _is_number обрабатывает OverflowError и возвращает штатный отказ вместо аварии;
- чрезмерно большая координата не принимается как конечное поддерживаемое измерение;
- чрезмерный sample_count приводит к диагностике о выходе за поддерживаемый диапазон расчёта длительности;
- валидатор не завершает CLI необработанным исключением.

Для file.size_bytes целочисленность и фактическое сравнение остаются в целочисленной арифметике, поскольку размер файла возвращается файловой системой как int.

Это ограничение относится к вычислительному представлению и не объявляет, что математически большие целые числа перестают быть целыми.

## 4. Воспроизводимый порядок проверки schema references

В документе 62 зафиксирована политика ссылок:
- разрешаются только локальные JSON Pointer;
- внешние URI и неразрешимые локальные указатели запрещены;
- литеральные данные внутри const/default/examples не интерпретируются как schema references.

Ранее наборы ключевых слов, задающих позиции вложенных схем, хранились как Python set. Порядок обхода set не гарантируется и может изменяться между процессами. Если в одной схеме несколько внешних ссылок, первой ошибкой могла становиться разная ссылка.

Теперь коллекции schema-bearing keywords заданы упорядоченными tuple:
- одиночные subschema keywords;
- массивы subschema;
- словари subschema.

Сам порядок элементов свойств JSON сохраняется при строгом разборе. Поэтому для неизменной схемы первый найденный недопустимый reference теперь стабилен.

Добавлен тест, в котором одновременно присутствуют внешние ссылки в $defs и properties. Три последовательных вызова должны выдавать одну и ту же первую ошибку, с приоритетом $defs.

## 5. Подтверждённые тесты

Добавлены четыре сценария:
1. CLI отклоняет числовое переполнение 1e999;

3. чрезмерно большая целая координата получает штатную ошибку, без OverflowError;
4. чрезмерный sample_count получает штатную ошибку при расчёте длительности.

## 7. Границы поддержки чисел

Числовые значения приводятся к Python int/float. Не поддерживается произвольная десятичная точность Decimal для всех полей. Вместо молчаливого переполнения или underflow такой вход отклоняется.

Если будущая метрологическая процедура потребует точного хранения десятичных дробей без округления, это должно стать отдельным изменением контракта:
- тип хранения;
- JSON Schema совместимость;
- арифметика сравнения;
- сериализация и контроль повторного чтения;
- тесты без потери точности.

Сейчас парсер выбирает более безопасный отказ, чем незаметную замену числового значения.
