## 1. Исходный сбой

Первичный подтверждённый сбой:
- workflow run: 45633908223;
- проверенный commit: 64725b01932c9160232bd5a458c3b19bd7813f4e;
- завершение: completed / failure;
- число тестов: 18;
- результат: 1 ошибка выполнения.

Ошибка возникла в тесте test_rejects_nonpositive_sample_rate. Тест передал частоту дискретизации, равную нулю. Валидатор корректно добавил сообщение о неположительной частоте, но затем в отдельной проверке согласованности длительности выполнил деление числа отсчётов на ту же нулевую частоту. Возник ZeroDivisionError.

Первичный лог GitHub Actions подтвердил место ошибки:
- файл: tools/giza_spatial/validate_vibration_manifest.py;
- функция: validate_manifest_payload;
- операция: sample_count / float(sample_rate).

Следовательно, проблема находилась не в тестовой среде и не в GitHub Actions. Это был дефект защитного условия в коде валидатора.

## 2. Исправление

В вычисление ожидаемой длительности добавлено обязательное условие: частота должна быть конечным положительным числом.

Теперь:
- нулевая частота получает штатную ошибку входных данных;
- отрицательная частота получает штатную ошибку входных данных;
- деление на неположительную частоту не выполняется;
- остальные проверки метаданных продолжаются без аварийного завершения.
