**Implemented scope:** Issue #7 §16–18, with §18 (epistemological core) implemented first, before any new cockpit panel.
**Status:** framework. 0 verified sources, 0 real geodetic objects, 0 live adapters, 0 promotable claims.
**Not implemented:** real source ingestion, real measurements, ASTRAEA/Ухо Планеты adapters, physical energy balance of Giza, any cockpit projection of this core.

## Why a core and not ten more panels

Sections 16 and 17 define passports and physical/evidence accounting. Section 18 explicitly requires that these be **projections of one canonical, versioned knowledge graph**, not separate documents and not a visual exercise. This package implements that kernel. The existing 10-view cockpit is untouched by this delivery; a later iteration may bind to the core, but creating panels is not accepted as implementation of §18.

## Canonical graph

`K = (N, E, T, V, P, Q)`: typed nodes, typed directed edges, temporal structure, versions, provenance and quality constraints. Every edge has a type and scope; a universal `related_to` link is rejected. Dependency edges run **from the dependent node to its prerequisite**; support/attack edges run **from the argument to the claim**. Corrections create a new node version plus an event; earlier versions are immutable.

## First-class epistemic objects

- **Claim** — stable ID, version, subject/predicate/value, scope, units/CRS where applicable, epistemic type separate from status, provenance, transformation chain, supporting and contradicting arguments, assumptions, prediction, revision conditions. Changing the statement, scope or grounding creates a new version with a diff.
- **Belief Structure Passport** — a readable structure of support chains, dependencies, critical nodes, alternatives, assumptions and independent checks. It has an explicit `quantitative_score: null`; it is never a trust score.
- **Conflict Object** — competing versions with their own provenance, divergence type, comparability and shared sources. Original claims are never averaged, silently selected or deleted. Resolution is **scoped**; new evidence can reopen a conflict without destroying the earlier decision.
- **Destroy / Revision Conditions** — structured predicates registered before confirmation data. A firing condition emits an event, moves the claim to the preregistered state and preserves the whole history. Post-hoc changes create a new condition version; `evaluate(..., version=1)` still applies the registered rule.
- **Ontology Passport** — versioned class definitions and allowed relations; a hypothesis cannot be typed as a physical measurement, an energy flow cannot be typed as a geological Entity, and a criterion change triggers an impact review.
- **Identity × Temporal** — material, spatial, structural, functional and genealogical continuity are kept separate; an `EntityState` never silently replaces or merges an `Entity`; split/merge creates lineage branches; criterion changes are versioned and reviewed.

## Passport projections

Ten passports (geometry/relation, energy/environment, uncertainty/evidence, temporal/state, observation, genesis, identity, conservation, dynamic/regime, boundary/coupling) are materialised **on demand** from the canonical graph. Inspecting a passport state creates nothing. `not_created`, `partial`, `unknown`, `not_applicable`, `blocked` and `complete` are distinguished; absence of a passport is not absence of an object, a property or data. A change to one canonical measurement invalidates the relevant cached projection; no source fact is duplicated.

## Uncertainty and evidence rules

- Source, measurement, interpretation, coverage, model and evidence-connectivity axes stay separate. Each has formal rubric criteria; author assessment and independent verification are stored separately. No multiplication into one percentage, colour or trust score.
- Covariance and correlations propagate through derived calculations. Unknown correlation is **not** silently treated as independence; if independence is assumed, it needs an explicit reason and the result is disclosed as approximate. Monte Carlo is seeded, sampled, versioned and deterministic.
- Cache keys include input IDs/versions, covariance, method, code version, configuration and assumptions. A dependency update invalidates only affected entries; stale results are removed, never returned.
- A draft/interval/Monte Carlo result cannot pass a gate that requires a full calculation.
- The evidence gate reports the weakest necessary axis and open conflicts structurally; it never outputs an aggregate number.

## Machine invariants (§18.11)

`INV-01` scope/provenance/version/status · `INV-02` support reaches primary observations · `INV-03` shared source is not independent confirmation · `INV-04` new dependency triggers review · `INV-05` conflicts never averaged or deleted · `INV-06` revision creates event and version · `INV-07` informal conditions require human review · `INV-08` state does not replace entity · `INV-09` ontology/identity criteria versioned · `INV-10` lazy passports · `INV-11` independent verification is not self-assessment · `INV-12` cache invalidation · `INV-13` approximation disclosure · `INV-14` no universal score.

`core.assert_invariants(graph, ...)` checks all fourteen programmatically; each has a negative test.

## Honest zero state

Creating a Claim, Conflict, passport or synthetic fixture does not create empirical evidence. `verified_sources`, `real_objects`, `live_adapters` and `promotable_claims` remain `0`. Paper mode and historical data only; no live feed, no auto trade, no bit→joule conversion, no physical energy transfer, no causality from resemblance.
